# English `data-lang` support for Custom Development widgets

## Objective

Add bilingual content support to the three widgets used by the Webflow Custom Development page:

- `widgets/hero-soluciones/hero-soluciones.js`
- `widgets/proceso/proceso-widget.js`
- `widgets/sustentabilidad/sustentabilidad-widget.js`

Each widget must render English when its root container has `data-lang="en"`. Spanish remains the default when the attribute is absent, empty, or unsupported.

## Architecture

Each widget will own a small internal content dictionary with `es` and `en` entries. A language resolver will read the widget root's `data-lang` attribute, normalize it to lowercase, accept `en`, and fall back to `es` for every other value.

Rendering will consume the selected dictionary instead of embedding user-visible Spanish strings directly in templates. Existing DOM structure, class names, assets, animations, and initialization behavior will remain unchanged.

## Widget behavior

### Hero solutions

All visible headings, descriptions, labels, and calls to action generated by the hero widget will come from its selected language dictionary.

### Process

All process-stage headings, descriptions, labels, and navigation text generated by the process widget will come from its selected language dictionary.

### Sustainability

All visible sustainability headings, descriptions, labels, and calls to action generated by the sustainability widget will come from its selected language dictionary.

## Compatibility and fallback

- `data-lang="en"` selects English.
- Missing `data-lang` selects Spanish.
- `data-lang="es"` selects Spanish.
- Unknown values such as `data-lang="fr"` select Spanish.
- Existing Spanish embeds continue working without changes.
- Multiple instances on one page resolve their language independently when the current widget architecture supports multiple roots.

## Testing

Tests will be written before production changes and must initially fail for the missing English behavior. They will verify:

1. Spanish output when `data-lang` is absent.
2. English output when `data-lang="en"`.
3. Spanish fallback for unsupported language values.
4. No remaining user-visible Spanish literals in English-rendered output for each widget.

Tests should exercise real widget rendering or the smallest exported language/content resolver that the existing architecture can support without adding test-only production APIs.

## Non-goals

- Adding languages beyond English and Spanish.
- Changing visual design, CSS, animations, images, or Webflow embed markup.
- Translating the shared Navbar or Footer.
- Moving translations to an external service or network-loaded JSON file.

## Success criteria

The three current Webflow embeds using `data-lang="en"` render fully in English, existing embeds without the attribute remain in Spanish, and the complete relevant test suite passes without errors.
